# Сайт ЦДУМ ПО (cdumpo.ru)

Официальный сайт Централизованного духовного управления мусульман Пензенской области («Муфтият Пензы»): время намаза, мечети, «Камень к камню» для Соборной мечети, «Жизнь уммы», календарь хиджры, кибла-компас, закят-калькулятор и админка для сотрудников.

**Стек:** Next.js 16 (App Router) · React 19 · TypeScript · Payload CMS 3 (админка внутри проекта, `/admin`) · PostgreSQL · Tailwind CSS 4 · pnpm.

Что за организация и как должен выглядеть сайт — в [PRODUCT.md](PRODUCT.md) и [DESIGN.md](DESIGN.md). План работ — [ROADMAP.md](ROADMAP.md). Как вести сайт сотрудникам — [docs/instrukciya-admin.md](docs/instrukciya-admin.md). Безопасность — [docs/security-plan.md](docs/security-plan.md).

## Что понадобится

- **Node.js 22** (подойдёт не ниже 20.9). Проверка: `node -v`.
- **pnpm.** Версия записана в `package.json`; проще всего включить её через Corepack: `corepack enable`.
- **PostgreSQL 17.** Два способа: Docker (`docker compose`) или встроенная база без Docker (ниже).
- **Git.**

## Скачать и установить

```bash
git clone git@github.com:azizov26/cdumpo.git
cd cdumpo
pnpm install
```

Затем создайте файл с настройками:

```bash
cp .env.example .env
```

Откройте `.env` и заполните:

| Переменная | Что это |
|---|---|
| `DATABASE_URI` | Строка подключения к Postgres (нужна для админки и данных из неё). Для локальной базы из этой инструкции оставьте как в примере: `postgres://cdumpo:cdumpo@localhost:5432/cdumpo` |
| `PAYLOAD_SECRET` | Нужна всегда. Длинная случайная строка, не короче 32 символов. Сгенерировать: `openssl rand -hex 32` |

> **Ключи и пароли хранятся только в `.env` на вашем компьютере.** Файл `.env` в git не попадает, и коммит с секретами блокируется автоматически. Настоящие ключи (хранилище, продакшен-база и т. п.) передаются лично, а не через чат, почту или репозиторий.

## Быстрый просмотр сайта (без базы и админки)

Чтобы просто посмотреть сайт, база не нужна: достаточно `.env` с `PAYLOAD_SECRET` и `pnpm dev`. Без базы публичные страницы открываются, а там, где данные берутся из админки (новости, контакты, баннер, расписание), показывается пустое состояние. Время намаза, небо, кибла, закят, календарь и остальные страницы работают как обычно. Админка и вход в неё без базы недоступны.

> Файл `.env` с `PAYLOAD_SECRET` нужен всегда, даже если админкой вы не пользуетесь: без секрета `pnpm build` падает на этапе сборки. Переменная `DATABASE_URI` нужна только когда подключаете базу.

## Запустить базу данных

**Вариант 1 — Docker:**

```bash
docker compose up -d
```

**Вариант 2 — без Docker** (встроенный Postgres, данные лежат в `.data/pg`):

```bash
pnpm db:dev
```

Команда занимает терминал: оставьте её запущенной, а остальное делайте в другом окне. Остановить — `Ctrl+C`.

## Запустить сайт

```bash
pnpm dev
```

Сайт откроется на <http://localhost:3000>, админка — на <http://localhost:3000/admin>.

При первом открытии `/admin` Payload предложит создать первого пользователя — он автоматически получает роль **администратор**. Остальных сотрудников администратор заводит в разделе «Сотрудники».

Схему базы в режиме разработки Payload подтягивает сам. Данных на сайте поначалу нет: там, где их нет, показывается пустое состояние, а не выдуманный контент.

### Посмотреть небо в разных состояниях

Добавьте к адресу `?sky=dawn`, `day`, `asr`, `evening` или `night`, например <http://localhost:3000/?sky=night>.

## Данные

**Время намаза** лежит в `src/data/prayer-times.json` (Пенза, 2026). Пересобрать из исходных файлов в `data/prayer-times/`: `pnpm prayer:build`.

**Новости со старого сайта** (необязательно). Список новостей и таблица редиректов уже в репозитории (`data/legacy/`). Чтобы залить их в локальную базу:

```bash
MEDIA=1 node scripts/scrape-cdumpo.mjs        # скачать картинки со старого сайта (в git они не попадают)
pnpm payload run scripts/import-legacy.ts      # импорт в Payload (можно запускать повторно)
LIMIT=5 pnpm payload run scripts/import-legacy.ts   # пробный прогон на пяти записях
```

Подробности про перенос — в этапе 7 [ROADMAP.md](ROADMAP.md).

## Команды

| Команда | Что делает |
|---|---|
| `pnpm dev` | Сайт для разработки, localhost:3000 |
| `pnpm build` | Продакшен-сборка |
| `pnpm start` | Запуск собранного сайта |
| `pnpm lint` | Проверка кода (ESLint) |
| `pnpm typecheck` | Проверка типов |
| `pnpm format` / `pnpm format:check` | Форматирование кода (Prettier) |
| `pnpm test` | Модульные тесты (Vitest) |
| `pnpm e2e` | Сценарии в браузере (Playwright): собирает сайт и проверяет страницы и доступность. Нужна запущенная база |
| `pnpm types` | Пересобрать `src/payload-types.ts` после правки коллекций |
| `pnpm payload migrate:create <имя>` | Создать миграцию после изменения схемы (обязательно: на проде схема меняется только миграциями) |
| `pnpm migrate` | Применить миграции |
| `pnpm secrets:check` | Проверить, что в репозитории нет ключей и паролей |
| `pnpm screens /путь` | Скриншоты страницы на 360, 768, 1280 и 1440 px и проверка горизонтальной прокрутки (нужен запущенный `pnpm dev`) |

Первый раз для `pnpm e2e` нужно поставить браузер: `pnpm exec playwright install chromium`.

## Продакшен-сборка локально

```bash
pnpm migrate     # схема базы — только миграциями
pnpm build
pnpm start       # http://localhost:3000
```

Перед запуском на хостинге задайте в окружении `DATABASE_URI`, `PAYLOAD_SECRET` и `NEXT_PUBLIC_SITE_URL` (адрес сайта, например `https://cdumpo.ru`; по умолчанию используется он). В продакшене сайт не запустится без `PAYLOAD_SECRET` длиной от 32 символов. Подробности деплоя будут описаны после выбора хостинга (этап 12 в [ROADMAP.md](ROADMAP.md)).

## Запуск на сервере (Docker)

Нужны Docker и Docker Compose на сервере. Файлы: [Dockerfile](Dockerfile), [docker-compose.prod.yml](docker-compose.prod.yml), образец настроек [.env.production.example](.env.production.example).

```bash
cp .env.production.example .env.production   # заполнить POSTGRES_PASSWORD и PAYLOAD_SECRET
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build
```

Что произойдёт: поднимется база, затем применятся миграции (`migrate`), затем запустится сайт на `127.0.0.1:3000`. Наружу сайт напрямую не открыт: перед ним ставится nginx (HTTPS, лимиты запросов, закрытая `/admin`). База из интернета недоступна. Загруженные в админке файлы лежат в томе `media`, база — в томе `pgdata`.

Обновление сайта: `git pull`, затем та же команда `up -d --build`. Секреты лежат только в `.env.production` на сервере и передаются лично.

> Образ и compose-файл **ещё не проверены на сервере** (в разработке Docker не запускался). Первый запуск стоит сделать на тестовой машине. Конфигурация nginx и бэкапы базы — следующие шаги этапа 12 в [ROADMAP.md](ROADMAP.md).

```

```

## Если что-то не работает

- **`cannot connect to Postgres`** — не запущена база. Запустите `docker compose up -d` или `pnpm db:dev` и перезапустите `pnpm dev`.
- **Порт 5432 занят** — уже работает другой Postgres. Остановите его или поменяйте порт в `docker-compose.yml` и в `DATABASE_URI`.
- **Порт 3000 занят** — Next.js возьмёт следующий свободный (3001); адрес будет в выводе команды.
- **Ошибка про `PAYLOAD_SECRET`** — заполните переменную в `.env` (см. выше).
- **После переименования страниц или маршрутов ошибки типов из `.next/types`** — выполните `pnpm exec next typegen`.
